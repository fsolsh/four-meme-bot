# FourMeme Bot 服务

## 📖 项目概述

FourMeme Bot 服务是一个基于 Web 的交互式应用程序，旨在自动化、管理并与“FourMeme”生态系统中的机器人进行交互。

它提供了一个用户友好的 Web 界面，用于机器人控制、实时交互和会话管理，并由健壮的 Java Spring Boot 后端提供支持。

该服务充当用户与自动化机器人流程之间的桥梁，支持无缝的命令执行、状态管理和安全访问控制。

---

## ✨ 核心功能

### 1. 用户身份验证与授权

- **安全登录系统**：用户必须通过身份验证才能访问机器人控制面板。系统采用标准登录流程来验证用户凭据。
- **会话管理**：维护安全的用户会话，确保只有经过身份验证的用户才能与机器人交互。

### 2. 机器人控制与管理（后端）

- **RESTful API**：暴露端点以处理各种机器人操作，例如启动、停止、发送命令和检索机器人状态。
- **状态管理**：跟踪机器人的生命周期和当前状态，确保命令可靠执行。

### 3. 交互式 Web 仪表盘（前端）

- **控制面板**：一个动态仪表盘，经过身份验证的用户可以在其中查看机器人状态、发送命令并实时监控输出。
- **异步通信**：利用 AJAX/Fetch API 与后端通信，无需刷新页面，提供流畅的单页应用（SPA）体验。

## 🛡️ 安全架构

安全性是 FourMeme Bot 服务的关键组成部分。应用程序实现了多层安全措施，以保护后端 API 和前端界面。

### 前端安全

- **路由守卫**：应用程序严格区分公共路由和受保护路由。如果用户在没有有效会话的情况下尝试访问仪表盘，会被自动重定向到登录页面。
- **令牌/会话处理**：来自前端的 API 请求包含必要的身份验证令牌或会话 Cookie。应用程序通过将用户重定向到登录页面来优雅地处理未授权的 API 响应（例如 HTTP 401）。
- **输入清理**：控制面板中的用户输入在发送到后端之前会进行清理，以防止跨站脚本（XSS）和注入攻击。

### 后端安全

- **控制器级保护**：API 端点受到保护，需要身份验证。缺少有效凭据的请求会在到达业务逻辑之前，在控制器或过滤器级别被拒绝。
- **CSRF 保护**：作为一个会修改状态的应用程序，Spring Security 的 CSRF 保护默认对非安全 HTTP 方法（POST、PUT、DELETE）启用，以防止跨站请求伪造攻击。
- **CORS 策略**：跨源资源共享被配置为仅允许来自受信任域的请求，防止未授权的外部网站与 Bot API 交互。

### 会话与凭据安全

- **安全 Cookie**：会话 Cookie 配置了 `HttpOnly`（防止客户端 JavaScript 访问）和 `Secure`（仅通过 HTTPS 传输）标志，以缓解会话劫持和 XSS 攻击。
- **密码哈希**：用户密码从不以明文存储。系统使用强加密哈希算法（例如 BCrypt）来验证凭据。

## 🛠️ 技术栈

- **后端**：Java、Spring Boot、Spring Web、Spring Security
- **前端**：HTML5、CSS3、原生 JavaScript（ES6+）
- **架构**：RESTful API、单页应用（SPA）模式

## 🚀 快速开始

### 先决条件

- Java JDK 11 或更高版本
- Maven 或 Gradle

### 安装与运行

1. 克隆仓库：

   ```bash
   git clone <repository-url>
   cd fourmeme-bot
   ```

2. 构建项目：

   ```bash
   mvn clean package
   ```

3. 运行应用程序：

   ```bash
   java -jar target/fourmeme-bot-<version>.jar
   ```

4. 通过 Web 浏览器访问应用程序：

   ```bash
   http://localhost:8080
   ```
